## 1. 主流平台能力对照总表
> 说明：✅=原生能力 / 🟡=部分支持或需变通 / ❌=不支持或需外接。下表为通用能力评估，具体数量上限以各平台套餐政策为准（见第 4 节）。
| 能力维度 | 飞书多维表格 | Notion | Airtable | Excel（含腾讯文档/WPS 在线表格） |
|---------|-------------|--------|----------|-------------------------------|
| 字段类型丰富度 | ✅ 很丰富（单选/多选/人员/货币/自动编号/公式/查找引用/关联等） | 🟡 基础（文本/数字/选择/日期/关系/汇总等） | ✅ 丰富（单选/多选/附件/自动编号/关联/Rollup/按钮等） | 🟡 无字段类型概念，用数据验证/格式约束模拟 |
| 跨表关联 | ✅ 关联+查找引用，可双向 | ✅ Relation+Rollup（需配置聚合） | ✅ Linked records+Rollup/Lookup | ❌ 无原生关联，用 VLOOKUP/XLOOKUP 模拟 |
| 公式能力 | ✅ 较强（IF/DATEDIF/COUNTIF/SUMIF 等，可引用其他表字段） | 🟡 类 JS 语法，无 COUNTIF/SUMIF，跨库靠 Rollup | ✅ 接近 Excel（IF/SUM/COUNT/DATEDIF 等，无 SUMIF/COUNTIF 需 Rollup） | ✅ 最强（900+ 函数，SUMIFS/COUNTIFS/XLOOKUP/IFS 全支持） |
| 自动化 | ✅ 记录新增/字段修改/定时/评论触发，动作丰富 | 🟡 付费版才支持，触发与动作较少 | ✅ 记录触发/定时/Webhook，动作丰富（免费版限次数） | ❌ 无原生自动化（需 Power Automate/VBA/腾讯文档工作流） |
| 智能体/Agent | ✅ 多维智能体（对话/定时/记录触发+知识库+工具权限） | ❌ 无配置化智能体（Notion AI 仅为生成式问答） | ❌ 无智能体（Airtable AI 仅为辅助；可外接 AI 工具） | ❌ 无智能体（需外接 Coze/扣子、Copilot、AI Builder 等） |
| 仪表盘/可视化 | ✅ 仪表盘、多视图、角色看板 | 🟡 数据库视图+图表块（功能有限） | ✅ Interfaces/Dashboard 视图 | 🟡 图表+透视表（在线版可视化成组较弱） |
| 多人协作与权限 | ✅ 实时协作、表级/视图级权限 | ✅ 页面级权限（粒度较粗） | ✅ 协作+基于表的权限 | 🟡 协作可用，权限粒度粗 |
| 成本门槛 | 🟡 智能体/部分自动化需付费套餐 | 🟡 自动化需付费（Plus 起） | 🟡 自动化/高级功能需付费 | ✅ 一般有免费或基础版 |
**一句话结论**：
- **飞书多维表格**：能力最全，适合需要"多表关联 + 自动化通知 + 智能体 + 仪表盘"的完整采购管理系统。
- **Airtable**：数据能力接近飞书，适合重视公式/关联/外部集成的数据驱动场景；但**没有配置化智能体**，自动化有额度。
- **Notion**：适合"文档 + 轻量台账 + 团队知识库"一体化场景；公式学习成本高，自动化与智能体能力弱。
- **Excel/在线表格**：适合轻量台账、复杂财务计算、一次性报表；几乎无自动化与智能体。

## 2. 字段类型与关联能力对照
### 2.1 常见采购字段在各平台的落法
| 本技能常用字段 | 飞书多维表格 | Notion | Airtable | Excel |
|--------------|-------------|--------|----------|-------|
| 供应商/订单编号 | 自动编号 | 文本（手动或公式拼接） | 自动编号 | 文本（可用公式生成） |
| 供应商类型（单选） | 单选 | Select | Single select | 数据验证下拉 |
| 供应品类（多选） | 多选 | Multi-select | Multiple select | 多列+勾选（弱） |
| 状态字段 | 单选 | Status/Select | Single select | 数据验证下拉 |
| 金额 | 货币 | Number | Currency | 数值+格式 |
| 日期 | 日期 | Date | Date/DateTime | 日期格式 |
| 人员/负责人 | 人员 | Person | Collaborator | 文本 |
| 附件（合同扫描件等） | 附件 | Files | Attachment | 附件/链接 |
| 跨表引用（如订单→供应商） | 关联字段 | Relation | Linked record | VLOOKUP/XLOOKUP |
| 聚合汇总（如按供应商汇总降本） | 查找引用/公式 | Rollup | Rollup/Lookup | SUMIF/SUMIFS |
### 2.2 关联能力对比要点
- **飞书**：关联字段支持双向关联视图，可在此基础上用「查找引用」把目标表字段带入当前表参与公式。导入 Excel 数据后关联需手动重建。
- **Notion**：`Relation` 是**双向**的，另一侧会自动生成反向关系属性；跨表取值只能用 `Rollup`（选择聚合方式：原值/计数/求和/平均等）。**Notion 公式无法直接引用其他库的字段**，这是与飞书/Airtable 最大的差异。
- **Airtable**：`Linked record` 双向关联；可添加 `Rollup`（对链接记录聚合）与 `Lookup`（把链接记录的字段原样带过来），公式字段可直接引用 `{关联字段}`。
- **Excel**：无关系模型，用 `VLOOKUP/XLOOKUP/INDEX-MATCH` 按唯一键匹配；数据变更不联动，容易产生不一致。

## 3. 核心公式替代方案
> 本节将本技能最常用的公式（见 [formulas-automations.md](formulas-automations.md) 第 1 节）在四个平台逐一给出等效实现。实现逻辑一致，仅语法与引用方式不同。
### 3.1 公式对照速查表
| 场景 | 飞书多维表格（原文） | Notion（formula） | Airtable（公式字段） | Excel（单元格） |
|------|--------------------|-------------------|---------------------|----------------|
| **TCO 总成本** | `年采购金额+年质检成本+年物流成本+年库存持有成本+年应急处理成本` | `prop("年采购金额")+prop("年质检成本")+prop("年物流成本")+prop("年库存持有成本")+prop("年应急处理成本")` | `{年采购金额}+{年质检成本}+{年物流成本}+{年库存持有成本}+{年应急处理成本}` | `=B2+C2+D2+E2+F2` |
| **风险评分 RPN** | `概率*影响*可检测性`（FMEA 三要素） | `prop("概率")*prop("影响")*prop("可检测性")` | `{概率}*{影响}*{可检测性}` | `=B2*C2*D2` |
| **供应商加权总分** | `质量*0.35+交付*0.25+服务*0.20+价格*0.20` | `prop("质量")*0.35+prop("交付")*0.25+prop("服务")*0.20+prop("价格")*0.20` | `{质量}*0.35+{交付}*0.25+{服务}*0.20+{价格}*0.20` | `=B2*0.35+C2*0.25+D2*0.2+E2*0.2` |
| **绩效评定等级判定** | 嵌套 `IF(总分>=90,"S",IF(>=80,"A",IF(>=70,"B",IF(>=60,"C","D"))))` | 嵌套 `if()`（语法见 3.3） | 嵌套 `IF()`（同左） | `=IF(B2>=90,"S",IF(B2>=80,"A",IF(B2>=70,"B",IF(B2>=60,"C","D"))))` |
| **库存预警状态** | `IF(库存<安全库存,"🔴 低库存",IF(库存>最高库存,"🟡 超储","🟢 正常"))` | 嵌套 `if()` | `IF({当前库存}<{安全库存},"🔴 低库存",IF({当前库存}>{最高库存},"🟡 超储","🟢 正常"))` | `=IF(B2<C2,"🔴 低库存",IF(B2>D2,"🟡 超储","🟢 正常"))` |
| **合同到期倒计时** | `DATEDIF(TODAY(),到期日期,"D")` | `dateBetween(prop("到期日期"),now(),"days")` | `DATEDIF(TODAY(),{到期日期},"d")` | `=DATEDIF(TODAY(),B2,"d")` |
| **到期/过期预警** | 嵌套 `IF(到期日期<TODAY(),"🔴 已过期",IF(DATEDIF(TODAY(),到期日期,"D")<=60,"⚠️ 即将到期","✅ 正常"))`（先日期比较判过期，DATEDIF 仅用于未过期分支） | `if(dateBetween(prop("到期日期"),now(),"days")<=0,"🔴 已过期",if(dateBetween(prop("到期日期"),now(),"days")<=60,"⚠️ 即将到期","✅ 正常"))` | `IF(DATEDIF(TODAY(),{到期日期},"d")<=0,"🔴 已过期",IF(DATEDIF(TODAY(),{到期日期},"d")<=60,"⚠️ 即将到期","✅ 正常"))` | `=IF(B2<TODAY(),"🔴 已过期",IF(B2-TODAY()<=60,"⚠️ 即将到期","✅ 正常"))` |
| **SPI 进度绩效指数** | `IF(PV>0, EV/PV, 1)` | `if(prop("PV")>0, prop("EV")/prop("PV"), 1)` | `IF({PV}>0,{EV}/{PV},1)` | `=IF(C2>0,B2/C2,1)` |
| **降本率** | `IF(原单价>0,(原单价-现单价)/原单价*100,0)` | `if(prop("原单价")>0,(prop("原单价")-prop("现单价"))/prop("原单价")*100,0)` | `IF({原单价}>0,({原单价}-{现单价})/{原单价}*100,0)` | `=IF(B2>0,(B2-C2)/B2*100,0)` |
| **年化节约额** | `(原单价-现单价)*年采购量` | `(prop("原单价")-prop("现单价"))*prop("年采购量")` | `({原单价}-{现单价})*{年采购量}` | `=(B2-C2)*D2` |
| **对账差额** | `对账金额-发票金额` | `prop("对账金额")-prop("发票金额")` | `{对账金额}-{发票金额}` | `=B2-C2` |
| **待付金额** | `应付金额-已付金额` | `prop("应付金额")-prop("已付金额")` | `{应付金额}-{已付金额}` | `=B2-C2` |
| **补货建议量** | `MAX(0, 安全库存*2-当前库存)` | `max(0, prop("安全库存")*2-prop("当前库存"))` | `MAX(0,{安全库存}*2-{当前库存})` | `=MAX(0,C2*2-B2)` |
| **按供应商汇总降本** | `[降本追踪表].FILTER(CurrentValue.[供应商] = [供应商名称]).[年化节约额].SUM()` | 建 Relation→Rollup（聚合=求和）指向降本库的年化节约额 | 建 Linked record→Rollup（Rollup=SUM） | `=SUMIF(降本表!A:A,A2,降本表!D:D)` |
### 3.2 需用 Rollup 替代的统计类公式
以下公式在本技能中属于**跨行统计**（对另一张表按条件汇总），飞书公式字段**不能在单条记录上直接写** `COUNTIF / SUMIF` 式统计（需按 formulas-automations.md 1.4/1.6/1.15 的官方写法：先建辅助字段，再用 `FILTER + CurrentValue + 聚合` 或仪表盘 AVG 统计）；**Notion 与 Airtable 的公式字段不支持跨表跨行统计**，需改用「关联 + 汇总」结构：
| 本技能公式 | 飞书写法 | Notion 替代 | Airtable 替代 |
|-----------|---------|------------|--------------|
| 准时交付率（统计延迟为 0 的订单占比） | 先建「是否准时(1/0)」辅助公式字段（见 formulas 1.4），再用仪表盘 KPI 卡 AVG 或 `采购订单台账.FILTER(CurrentValue.[是否准时] = 1).COUNT()` 统计 | 建 Relation 到订单表 → Rollup 选择「count」+ 筛选视图辅助 | 建 Linked record → Rollup（count）分字段统计，再在公式字段 `=按时数/总数` |
| 按供应商汇总降本 | `SUMIF(...,年化节约额)` | Relation → Rollup（聚合=求和） | Linked record → Rollup（SUM） |
| 供应商数量/品类份额统计 | `COUNTIF / SUMIF` | Relation → Rollup（count/sum） | Linked record → Rollup（count/sum） |
> 💡 通用做法：**在 Notion/Airtable 里，任何"按某分类统计另一张表的数值"需求，都遵循三步**——①两表建关联（Relation/Linked record）→ ②在目标表加 Rollup 字段选聚合方式 → ③需要二次计算时再引用该 Rollup 值写公式。
### 3.3 Notion 公式语法速记（与飞书差异最大）
```
引用字段：prop("字段名")
文本拼接：concat(prop("A"), " - ", prop("B"))
日期天数差：dateBetween(prop("到期日期"), now(), "days")
取绝对值：abs(prop("偏差"))
条件判断：if(条件, 真值, 假值)
取大/小值：max(a, b) / min(a, b)
数字格式化：format(prop("金额"))
```
> ⚠️ Notion 公式**没有** `DATEDIF / COUNTIF / SUMIF / TODAY()`，且公式引用的字段必须存在于**同一数据库**，跨库只能靠 `Rollup`。
### 3.4 Airtable 公式语法速记
```
引用字段：{字段名}
条件判断：IF(条件, 真值, 假值)
日期天数差：DATEDIF(TODAY(), {到期日期}, "d")
取绝对值：ABS(数值)
取大/小值：MAX(a, b) / MIN(a, b)
拼接：CONCATENATE({A}, " - ", {B})
```
> ⚠️ Airtable 没有 `SUMIF / COUNTIF`（跨行统计用 Rollup），`SUM / COUNT` 需在 Rollup 字段中使用；单个公式字段只能操作**当前记录**及其关联的**链接记录**。
### 3.5 Excel 特殊建议
- **跨表引用**：用 `XLOOKUP/VLOOKUP`，主键（如供应商编码）必须唯一且格式一致。
- **预警高亮**：用「条件格式」替代自动化的颜色标记（如库存低于安全库存自动标红）。
- **下拉约束**：用「数据验证 → 序列」模拟单选/多选，保证录入规范。
- **到期提醒**：Excel 无定时推送，可结合「条件格式 + 公式列」在打开文件时看到提醒；如需推送需接 Power Automate 或腾讯文档工作流。

## 4. 自动化与智能体能力上限说明
> **智能体是本技能中高度依赖飞书平台付费能力的功能**，其他平台无法等量复刻，请按下列说明评估取舍。
### 4.1 各平台自动化与智能体能力上限
| 平台 | 自动化能力 | 智能体/Agent 能力 | 关键限制与上限提示 |
|------|-----------|------------------|-------------------|
| **飞书多维表格** | 记录新增/字段修改/定时/评论触发；动作含发消息、建记录、改字段 | ✅ 多维智能体：Prompt 四段式+工具权限+触发器组合+知识库，5 个标准方案均可落地 | 自动化与智能体数量、触发频次受**套餐等级**限制；智能体为**付费能力**，需在飞书多维表格设置中确认账号套餐（个人版/团队版/专业版/企业版）是否包含及配额。以官方帮助中心当前套餐说明为准 |
| **Notion** | 自动化（Automations）：记录创建/属性变化/定时/按钮触发 | ❌ 无配置化智能体；Notion AI 仅做生成式问答，不能自主读写表格 | 自动化**仅 Plus/Business 及以上套餐**提供，免费版不可用；触发类型与动作较少；无知识库式智能体，需外接（如 Coze 扣子 + Notion API） |
| **Airtable** | 自动化：记录创建/更新、定时、Webhook；动作丰富 | ❌ 无智能体；Airtable AI 为辅助能力（生成文案/公式等）；可通过 Interfaces 搭建自用界面 | 免费版自动化**每月约 100 次运行**，付费套餐按运行次数/流程数扩容；无内置 Agent，可用 Zapier/Make + 大模型 API 外接构建"伪智能体" |
| **Excel/在线表格** | 无原生自动化 | ❌ 无智能体 | 桌面版可用 **VBA 宏**（需启用宏）；在线版可接 **Power Automate / 腾讯文档工作流 / WPS 宏**做轻量定时与推送；智能体需外接 Coze/扣子、Copilot、AI Builder 等 |
### 4.2 智能体方案降级路线（非飞书用户）
原技能 5 个智能体方案（台账管家/合同预警/对账核对/数据分析师/风险预警）在非飞书平台的等价替代：
| 原智能体方案 | Notion/Airtable/Excel 降级方案 | 保留的能力 | 丢失/弱化的能力 |
|-------------|-------------------------------|-----------|----------------|
| 台账管家（日常运维） | 视图筛选 + 条件格式 + 手动检查清单 | 数据规范性检查 | 主动巡检、自然语言对话 |
| 合同预警（主动监控） | 自动化/定时触发 + 邮件/消息通知 | 到期预警推送 | 上下文问答、自动生成续签建议 |
| 对账核对（财务协同） | 公式差额列 + 条件格式标红 + 人工复核流程 | 差异识别 | 自动生成核对报告、智能建议 |
| 数据分析师（月度报告） | 透视表/图表 + 模板报告，或外接 AI 工具生成 | 数据汇总可视化 | 自动撰写分析结论 |
| 风险预警（主动监控） | 定时自动化 + 阈值判定 + 通知 | 阈值触发提醒 | 风险归因分析、主动升级策略 |
> 结论：**自动化类能力可通过各平台自有自动化或外接工具（Zapier/Make/Coze）重建约 70-80%**；**智能体类交互能力（自然语言对话、知识库问答）在飞书之外基本无法原生复刻**，需外接大模型工具，且需处理 API/权限/安全合规。

## 5. 平台迁移评估路径
### 5.1 三步决策法
```
第 1 步：评估业务复杂度
  - 表数量 <= 5 张、无复杂公式/自动化 → 轻量方案即可（Excel/Notion）
  - 表数量 5-12 张、有预警/汇总需求 → 考虑 Airtable 或飞书
  - 表数量 >= 12 张、需智能体/角色看板/权限 → 首选飞书
第 2 步：评估团队与环境
  - 是否已有飞书/企业微信等生态？→ 优先留在飞书
  - 是否已有 Notion/Airtable 付费账号？→ 降低迁移成本
  - 是否有 IT 能力做 API 外接？→ 可补齐自动化/智能体短板
第 3 步：评估长期投入
  - 自动化与智能体是否核心诉求？→ 是则留飞书或外接
  - 纯台账+报表？→ Excel 足够
  - 文档+表格一体化知识库？→ Notion 体验最好
```
### 5.2 场景-平台适配矩阵
| 业务场景 | 推荐平台 | 原因 |
|---------|---------|------|
| 完整 SRM（23 表全量 + 智能体 + 角色看板） | ✅ 飞书 | 能力最全，唯一原生支持智能体 |
| 12 张表中型系统，重视公式与外部集成 | 🟡 Airtable 或 飞书 | Airtable 数据能力强，智能体需外接 |
| 小型团队轻量台账（≤5 表）+ 文档知识库 | 🟡 Notion | 文档化协作体验好，自动化弱 |
| 复杂财务计算/一次性报表/单机使用 | ✅ Excel | 公式最强、零门槛 |
| 已有飞书生态（IM+文档+审批） | ✅ 留飞书 | 无需迁移，协作与权限最顺手 |
| 已有 Notion/Airtable 生态且不想付费 | 🟡 留原平台 + 按本指南降级 | 用公式替代方案补数据能力，弱化自动化/智能体 |
### 5.3 三个典型迁移场景示例
**场景 A：从飞书迁往 Airtable（适合数据驱动、重公式轻智能体的团队）**
- 可迁移：23 张表的字段结构、关联、90% 公式（改写语法）、仪表盘（用视图/Interface）
- 需重建：自动化（重写触发器与动作）、5 个智能体（降级为 自动化+Interface，或外接 AI）
- 迁移步骤：①导出飞书各表为 CSV → ②在 Airtable 建表（字段类型映射见第 2 节）→ ③导入数据 → ④重建 Linked record → ⑤添加 Rollup/Lookup → ⑥重写公式 → ⑦重建自动化 → ⑧校验数据一致性
**场景 B：从飞书迁往 Notion（适合重文档、轻自动化的团队）**
- 可迁移：表结构（基础字段）、静态数据、阅读型视图
- 需重写：所有跨表汇总改为 Relation+Rollup；公式全部改写为 Notion 语法
- 需放弃：人员字段、自动编号、复杂自动化、智能体（降级为页面+AI 问答）
**场景 C：从飞书迁往 Excel（适合个人/单机、一次性台账）**
- 可迁移：全部数据、计算逻辑（用普通公式重写）、视图（用筛选/透视表）
- 需放弃：实时协作、自动化推送、智能体、仪表盘联动
- 建议：以"工作表=数据表 + 数据验证约束 + 条件格式预警 + 透视表报表"的方式最大程度还原功能

## 6. 迁移注意点与常见限制
| 迁移项 | 主要风险 | 应对措施 |
|--------|---------|---------|
| **关联字段重建** | 飞书关联/查找引用无法直接迁移，导入后变文本 | 先导入为文本→全部基础表导入完→再在各平台重建 Relation/Linked record |
| **自动化丢失** | 跨平台自动化无法直接迁移，需全部重建 | 迁移前梳理自动化清单（触发类型/条件/动作），在新平台逐一重建并测试 |
| **公式语法差异** | 同一逻辑语法完全不同（尤其 Notion 类 JS 语法） | 对照第 3 节改写；Notion 无 COUNTIF/SUMIF，提前改为 Rollup 结构 |
| **统计类公式失效** | COUNTIF/SUMIF 在 Notion/Airtable 公式字段不可用 | 改用"关联+Rollup"聚合，再做二次公式 |
| **字段类型映射** | 单选/多选/人员/附件/自动编号等无一一对应 | 按第 2.1 节映射表转换；自动编号在 Notion 需用公式或手动编号 |
| **权限模型差异** | 飞书表级/视图级权限、Notion 页面级、Airtable 表级，粒度不同 | 按团队角色重新设计权限，敏感字段用视图隐藏（飞书/Airtable）或页面拆分（Notion） |
| **智能体能力落差** | 非飞书平台无配置化智能体 | 按 4.2 节降级路线，或外接 Coze/扣子 + 平台 API |
| **日期与数字格式** | 导出导入后日期/金额格式混乱（如 2026/8/15、50 万） | 迁移前按 data-migration.md 清洗规则统一（YYYY-MM-DD、纯数字），导入后再校验 |
| **历史数据一致性** | 新旧系统并行期数据不一致 | 并行运行 1-2 周，设置"历史/新数据"标记，双写校验后再切换 |

## 7. 选型决策建议
1. **默认仍以飞书多维表格为主**：本技能全部能力（23 表、50+ 公式、12 自动化、5 智能体、仪表盘）在飞书上开箱即用，是唯一无降级的完整方案。
2. **非飞书用户请先明确核心诉求**：是"要数据管理能力"还是"要自动化+智能体交互"。前者在 Airtable/Excel 可基本还原，后者必须外接工具或考虑购买飞书套餐。
3. **动手前先做一次能力差距评估**：把本技能的 12 个自动化与 5 个智能体逐条对照第 4 节，标注"可原样/需重建/需外接/需放弃"，再决定迁移还是停留。
4. **成本对比**：飞书（智能体/自动化付费）> Airtable（自动化付费）≈ Notion（自动化付费）> Excel（免费为主）。请结合团队规模与付费意愿选择。
5. **迁移后务必验收**：参照 [quality-checklist.md](quality-checklist.md) 与 [value-measurement.md](value-measurement.md) 对迁移结果做功能与价值双重验收。
